# IoU 0.1 Alpha 8

Payment and exemption histories now show prominent, direction-specific titles, distinct icons, and an explicit **مبلغ الإعفاء** or **مبلغ الدفعة** label. Notes appear separately and cannot hide the transaction type. Debt summaries separate cash paid from waived amounts, and mixed closure remains **مغلق بسداد وإعفاء**. Cancelled records are clearly marked.

Fixed a transaction-form reset when the privacy lock unmounts the screen. Previously, choosing an exemption and partial amount from the person's page could revert to a full cash payment after backgrounding and PIN unlock. The whole session now stays in memory above the lock: type, amount mode, direction, amount, actual date, note, pending submission, and saved receipt. Returning after a successful save keeps the receipt, preventing a submit-ready form from reappearing. Explicit Back, leaving a completed session, restoration, or opening a new session clears the draft. Late callbacks cannot overwrite a replacement session.

This prevents the reset for new submissions. Existing records keep their saved type; the app does not guess which historical payment was intended as an exemption. To correct an affected old record, cancel the incorrect payment from its history entry and record the exemption with the original amount and transaction date.

Install `iou-0.1.0-alpha.8.apk` over the previous alpha. Android version code is `8`; production package, signing key and existing data remain unchanged. Testing uses an isolated Android 16 emulator with synthetic records.
