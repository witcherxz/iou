# IoU 0.1 Beta 2

This release fixes folder backups that reported an error even though Dropbox had saved the new file.

- Android folder backups allow a short delay for a cloud provider to make a saved file readable. Verification retries read the same file without creating or writing another copy. The backup succeeds only after its contents match exactly; persistent failures remain visible and preserve any verified recovery snapshot.
- Cleaning up old snapshots is best effort. If a provider cannot list or remove older copies after all backup files are verified, the completed save remains successful and extra history may be retained.

Install `iou-0.1.0-beta.2.apk` over Beta 1. Android version code is `12`; the production identity, signing key and backup formats are unchanged. Existing ledger data and backups remain compatible.

Validation reproduced `FOLDER_SNAPSHOT_READ` on Dropbox Android 488.2.2 using an isolated test account. With the fix, complete backups and shorter rewrites passed exact JSON, HTML and four-CSV comparisons. Recovery after restarting the Dropbox process restored the entire test ledger, including payments, waived amounts, installments and edit history. Earlier snapshots remained unchanged, and no empty files appeared in the candidate tests. The separately reported empty-file symptom was not reproduced.

TypeScript and 1,489 integrated, release and native compatibility checks passed. The production APK is built and signed by GitHub Actions; the locally repackaged emulator candidate is not a release artifact.

Both GitHub workflows passed. The independently verified production APK also passed an emulator upgrade and Dropbox save: all 11 copied files were nonempty, the current backup/report/spreadsheets matched exactly, and earlier snapshots were preserved.
