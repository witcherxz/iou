# IoU 0.1 Alpha 4

This update improves Android folder backups and makes the manual Drive steps clearer.

- **Google Drive:** after sharing the report, choose Drive. If it is hidden, open **المزيد** and scroll the apps list; then finish with **تحميل** or **حفظ** inside Drive. ADB testing on a Samsung S24 Ultra reached Drive's upload screen successfully without changing the selected backup folder or uploading a test copy.
- **Folder backups:** rewriting an existing Android document now explicitly truncates it first, preventing old trailing bytes when the new backup or report is shorter. Immutable recovery snapshots are retained before updating the readable files.
- **Accurate errors:** if a recovery snapshot was verified but a report or companion file failed, the app explains that partial result. It does not mark the entire backup as successful. Diagnostic logs contain only a fixed error code, without file paths or ledger contents.
- Automatic biometrics from Alpha 3 remain included. Automatic prompting, successful entry, cancellation without loops and PIN fallback were checked on the connected S24 Ultra.

Install `iou-0.1.0-alpha.4.apk` over the previous alpha. Android version code is `4`; the production package, signing key, records and PIN remain compatible. The build contains no demo ledger. Verify the download with the accompanying SHA-256 file.

Automated provider checks reproduce non-truncating writes and incomplete companion updates. On-device testing then reproduced a remaining Dropbox snapshot-write failure (`FOLDER_SNAPSHOT_IO`); full Dropbox folder recovery is not verified in Alpha 4. Alpha 5 follows up with provider metadata and new-document handling. Manual Drive upload completion is confirmed by Drive after the user saves the file.
