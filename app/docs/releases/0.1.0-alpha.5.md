# IoU 0.1 Alpha 5

This update preserves unfinished entries and improves backup and recovery through Android document providers such as Dropbox.

- Adding or cancelling a new person keeps the filled entry. Amount, note, dates, direction, installments, and selected person survive temporary background/lock transitions; closing or saving the entry clears the draft. Drafts stay in memory during the current app session.
- Android folder backups use the provider's actual filenames, paired with their document identifiers. Version selection remains tied to the selected file even when filenames repeat or listing order changes.
- Android backups write through an owning output stream that closes the provider document before verification and truncates old contents. Newly created files are not created a second time while provider metadata is still updating.
- The app validates recovery copies before updating current files and reports incomplete saves accurately. Unrelated or unreadable files are preserved during history cleanup.
- Metadata and writes use the existing folder permission. No new storage permission or account connection is requested.
- Automatic biometrics, PIN fallback, clearer manual Drive instructions, and full/partial forgiveness remain included.

Install `iou-0.1.0-alpha.5.apk` over the previous alpha. Android version code is `5`; the production package and signing key remain unchanged. Existing records and PINs are preserved. Verify the APK with its accompanying SHA-256 file.

The native provider update requires this APK; earlier installed versions do not gain it automatically. Device save and recovery validation will be recorded after the production build is installed.

Validation before publication: 1,254 automated checks, TypeScript, eight isolated Expo form-flow scenarios, seven privacy-gate lifecycle scenarios, and six asynchronous backup-hook scenarios passed.
