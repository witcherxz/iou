# IoU 0.1 Beta 1

The project now enters beta for testing and stabilization. This release improves recovery from interrupted backups, Android reminders and Arabic labels.

- Android file restore opens the picker correctly and keeps the selected backup through PIN unlock for a fresh restore preview. Locking again or editing the ledger before confirmation cancels replacement.
- Folder restore chooses the newest valid backup, including a snapshot newer than an older valid main file.
- A failed backup or older local recovery keeps automatic writes paused across cancellation and restart. Review the ledger and save explicitly, or change the destination, before automatic writes resume. Existing-backup confirmation still applies when retrying.
- Protected backup passwords use a native worker and exports now encode correctly across Android and browsers. Earlier Android files affected by the SDK byte-encoding mismatch can be recovered inside IoU and exported again; password authentication remains required. The portable encryption format is unchanged.
- Each shared export has its own file so another export cannot replace data a receiving app is still reading. Protected restore stops when its private screen closes, including while checking a password.
- Blocked Android notifications or reminder channels are identified with an **إعدادات الجهاز** action. Recent pending reminders are checked against current debts and preferences before catch-up; old or superseded alerts are removed. Schedules also refresh for date, timezone and meaningful clock changes.
- Arabic selector and button labels use their available width. Compact status badges and due-date rows receive targeted layout fixes, including larger-font support.

Install `iou-0.1.0-beta.1.apk` over the previous alpha. Android version code is `11`; production identity and signing key are unchanged. Existing ledger data and backups remain compatible.

TypeScript, 1,475 integrated checks, 17 actual backup hook/store/host scenarios and 19 browser history workflows passed during preparation. Emulator checks passed for interrupted folder recovery, preserved records, Android notification delivery/settings/relaunch/reboot and larger Arabic labels. Actual protected Android exports open independently in Node and offline Chrome, with exact ledger and spreadsheet contents. Signed-release artifact verification follows the build.

Validation covers emulator/offline behavior. Real cloud-provider upload and restore with a signed-in account remain unverified. Direct Google Drive authorization stays disabled; manual sharing and file/folder recovery remain available.
